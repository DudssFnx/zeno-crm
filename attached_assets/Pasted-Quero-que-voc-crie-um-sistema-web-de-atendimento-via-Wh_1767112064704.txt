Quero que você crie um sistema web de atendimento via WhatsApp, multi-contas, com visual e funcionamento parecidos com ferramentas como Chatwoot ou CWMKT (cwmkt.com.br).

O foco é ser:
- Uma **inbox compartilhada** para o time de vendas/atendimento,
- Com **múltiplas contas de WhatsApp**,
- Com **etiquetas (tags)** e **estágios de funil**,
- Com **webhooks** e **automações básicas**,
- E uma interface **parecida com WhatsApp Web + Chatwoot** (lista de conversas à esquerda, chat no meio, detalhes do contato à direita).

⚠️ SOBRE A INTEGRAÇÃO COM WHATSAPP

- NÃO use API oficial do WhatsApp.
- NÃO implemente scraping direto, automação ou engenharia reversa do WhatsApp Web.
- Crie uma camada de integração chamada, por exemplo, `WhatsAppGateway` (ou `MessagingGateway`), que por enquanto será **mock/stub**.
- Essa camada deve expor métodos bem claros:
  - `startSession(whatsappAccountId)`
  - `getQrCode(whatsappAccountId)`
  - `sendMessage(whatsappAccountId, toPhone, content)`
  - `disconnectSession(whatsappAccountId)`
- A implementação atual será fake: apenas retorna dados simulados, loga no console e aciona o restante da lógica interna.
- A arquitetura deve deixar evidente que depois eu posso trocar essa implementação mock por qualquer provedor que eu quiser (inclusive um que faça o papel do “CWMKT da vida”).

Ou seja:
Você constrói todo CRM, inbox, UI, filas, etiquetas, webhooks e deixa só um **ponto de integração desacoplado** para o WhatsApp.

## CAMADA WHATSAPPGATEWAY (mock)

Criar algo como:

- Interface `IWhatsAppGateway` com métodos:
  - `startSession(whatsappAccountId: string): Promise<void>`
  - `getQrCode(whatsappAccountId: string): Promise<{ qrData: string }>`
  - `disconnectSession(whatsappAccountId: string): Promise<void>`
  - `sendMessage(whatsappAccountId: string, toPhone: string, content: string): Promise<{ externalMessageId: string }>`
- Implementação `MockWhatsAppGateway`:
  - `getQrCode` → retorna um objeto com `qrData` simulando um texto base64 ou string que possa virar QR code no frontend.
  - `sendMessage` → apenas loga e retorna um id fake.
  - Nada aqui faz contato real com o WhatsApp, apenas simula.

Toda lógica de criar Conversation, Contact, Message etc. fica em **Services do backend**, não dentro do gateway.

## ROTAS DO BACKEND (ESTILO CHATWOOT)

### Autenticação
- POST /auth/register → cria empresa + usuário admin
- POST /auth/login → tokens
- POST /auth/refresh → refresh token

### Gestão de usuários (admin)
- GET /users
- POST /users
- PUT /users/:id
- DELETE /users/:id

### Contas de WhatsApp
- GET /whatsapp-accounts
- POST /whatsapp-accounts
- PUT /whatsapp-accounts/:id
- DELETE /whatsapp-accounts/:id
- POST /whatsapp-accounts/:id/start-session → chama gateway.startSession
- GET /whatsapp-accounts/:id/qr → chama gateway.getQrCode
- POST /whatsapp-accounts/:id/disconnect → gateway.disconnectSession

### Contatos
- GET /contacts
- GET /contacts/:id
- POST /contacts
- PUT /contacts/:id

### Etiquetas
- GET /tags
- POST /tags
- PUT /tags/:id
- DELETE /tags/:id

- POST /contacts/:id/tags → adicionar tag
- DELETE /contacts/:id/tags/:tagId → remover tag

Ao alterar as tags de um contato:
- Disparar evento interno `contact.tag.changed` com payload (companyId, contactId, oldTags, newTags, userId).
- Enfileirar para webhooks.

### Conversas (Inbox)
- GET /conversations
  - filtros:
    - status
    - whatsappAccountId
    - tagId
    - assignedToUserId (ex.: “Minhas conversas”)
- GET /conversations/:id
- POST /conversations/:id/assign → atribuir agente
- POST /conversations/:id/status → alterar status (open/pending/resolved/closed)

### Mensagens
- GET /conversations/:id/messages
- POST /conversations/:id/messages
  - direction sempre `outgoing` aqui (mensagem para cliente)
  - chama WhatsAppGateway.sendMessage
  - grava mensagem no banco

- POST /conversations/:id/internal-notes
  - cria mensagem com direction = `internal_note` (não enviada ao cliente, só para o time)

### Webhooks
- GET /webhooks
- POST /webhooks
- PUT /webhooks/:id
- DELETE /webhooks/:id

Eventos que devem disparar webhooks:
- `contact.tag.changed`
- `message.incoming`
- `conversation.status.changed`

Estrutura do payload do webhook:
- `event`: string
- `timestamp`: ISO string
- `data`: objeto com campos da entidade (ex.: contact, conversation, message)

Se `secret` estiver definido, assinar payload com HMAC-SHA256 e enviar cabeçalho `X-Signature`.

### Endpoint de simulação (dev)
- POST /dev/simulate-incoming-message
  - body: { whatsappAccountId, phoneNumber, content }
  - se não existir Contact, cria.
  - se não existir Conversation aberta, cria.
  - grava Message direction = `incoming`.
  - dispara evento `message.incoming` para webhooks.

## FRONTEND – VISUAL TIPO CHATWOOT + WHATSAPP WEB

### Layout geral (dashboard)

Ao logar, o usuário cai numa tela com:

- Topbar simples com:
  - Nome da empresa
  - Nome do usuário
  - Botão de logout

- Corpo dividido em 3 colunas:

**1) Coluna Esquerda – Lista de conversas (Inbox)**
- Parecido com Chatwoot:
  - Filtros no topo:
    - Seletor da conta de WhatsApp (dropdown)
    - Filtros de status: Todas | Abertas | Pendentes | Resolvidas | Fechadas
    - Filtro “Minhas conversas” vs “Todas”
  - Campo de busca (por nome ou telefone do contato).
- Lista de conversas:
  - avatar (inicial do nome se não tiver foto)
  - nome do contato
  - snippet da última mensagem
  - horário da última mensagem
  - pequena “pill” com a etiqueta principal (se houver)
  - ícone ou cor diferente se estiver atribuída ao próprio agente

**2) Coluna Central – Chat**
- Cabeçalho:
  - Nome do contato
  - Número de telefone
  - Conta de WhatsApp usada
  - Status da conversa (com dropdown para mudar open/pending/resolved/closed)
  - Indicação do agente responsável
- Corpo:
  - Histórico de mensagens em formato de bolhas:
    - `incoming` alinhado à esquerda (cor A)
    - `outgoing` alinhado à direita (cor B)
    - `internal_note` com estilo diferente (fundo neutro, ícone de “nota interna”)
- Rodapé:
  - Campo de texto multi-linha
  - Botão de enviar
  - Suporte a:
    - Enter → enviar
    - Shift+Enter → quebra de linha
  - Dropdown para escolher de qual conta de WhatsApp será enviada a mensagem (caso o agente tenha acesso a mais de uma).

**3) Coluna Direita – Detalhes do contato**
- Card com:
  - Avatar grande
  - Nome
  - Telefone
  - Conta de WhatsApp
- Campo de notas (textarea editável, salvando automaticamente)
- Seção “Etiquetas”:
  - Listar tags aplicadas como chips coloridos
  - Botão “Adicionar etiqueta” (abre select de tags)
  - Botão para remover etiqueta em cada chip
- Se quiser, adicionar uma linha do tempo simples do funil (mostrar as principais tags aplicadas em ordem de data).

### Outras telas

- Tela de login
- Tela de gestão de usuários (apenas admin)
- Tela de gestão de contas de WhatsApp:
  - Lista de contas
  - Botão “Iniciar sessão” (mostra QR fake)
  - Mostrar status: conectado / pendente QR / desconectado
- Tela de gestão de etiquetas
- Tela de gestão de webhooks
