REPLIT PROMPT — WHATSAPP CRM AUTOMATION HUB
TYPEBOT-LIKE FLOWS + WASPEED-LIKE INBOX + READY WELCOME MENU
BAILEYS (Node.js) + SOCKET.IO

IMPORTANT:
- Do NOT implement any stealth, evasion, or bypass of WhatsApp detection.
- Presence updates (typing/recording) are allowed ONLY for UX, rate-limited.
- Automation MUST stop immediately when a human operator takes over.
- ZERO MESSAGE LOSS IS MANDATORY.

================================================
CORE RULE (NON-NEGOTIABLE)
================================================

EVERY inbound WhatsApp message MUST:
- be received
- be stored
- create or update a conversation
- appear instantly in the panel

This must work for:
- unknown contacts
- chats never opened
- inbound-first messages

NO message can be lost.

================================================
1) AUTOMATION ENGINE (TYPEBOT-LIKE)
================================================

Implement a node-based flow engine:

Flow {
  id,
  name,
  status: "draft" | "published",
  triggers: [],
  startNodeId,
  nodes: [],
  createdAt,
  updatedAt
}

FlowSession {
  chatId,
  flowId,
  currentNodeId,
  variables,
  state: "active" | "paused" | "handoff" | "ended",
  startedAt,
  lastInteractionAt
}

RULES:
- Only one active flow per chatId
- If session.state === "handoff", automation MUST NOT send messages

================================================
2) SUPPORTED NODE TYPES
================================================

- SEND_TEXT (supports emojis + variables)
- ASK_INPUT (validate user reply)
- CONDITION (if / else)
- SET_TAG
- MOVE_STAGE
- ASSIGN_QUEUE / ASSIGN_AGENT
- SEND_MEDIA (image / pdf / audio)
- HANDOFF_TO_HUMAN
- END

Variables example:
{{name}}, {{first_name}}, {{phone}}

================================================
3) FLOW TRIGGERS
================================================

Flows can start when:
- First inbound message (new conversation)
- Conversation stage == "NEW"
- Keyword match
- Tag added
- Webhook trigger

================================================
4) READY-TO-USE WELCOME MENU FLOW
================================================

FLOW NAME:
"Welcome Menu"

TRIGGER:
- First inbound message OR stage == "NEW"

--------------------------------
NODE 1 — SEND_TEXT
--------------------------------
Text:
"Bem-vindo(a)! 👋
Escolha uma opção:
1️⃣ Financeiro
2️⃣ Atendimento
3️⃣ Pós-vendas
4️⃣ Como comprar no atacado"

--------------------------------
NODE 2 — ASK_INPUT
--------------------------------
variableName: menu_choice
validValues: ["1","2","3","4"]

On invalid reply:
Send:
"Opção inválida 😅
Responda com 1, 2, 3 ou 4."

--------------------------------
NODE 3 — CONDITION (menu_choice)
--------------------------------

IF menu_choice == "1" (FINANCEIRO):
- Add tag: FINANCEIRO
- Move stage: Financeiro
- Assign queue: Financeiro
- Send text:
"Perfeito! 💳 Vou te encaminhar para o Financeiro.
Por favor, informe:
• Nome ou Empresa
• Motivo do contato (boleto, cobrança, nota, etc.)"
- HANDOFF_TO_HUMAN

IF menu_choice == "2" (ATENDIMENTO):
- Add tag: ATENDIMENTO
- Move stage: Atendimento
- Assign queue: Atendimento
- Send text:
"Certo! 👨‍💻 Nosso time de Atendimento vai te ajudar.
Descreva rapidamente sua dúvida."
- HANDOFF_TO_HUMAN

IF menu_choice == "3" (PÓS-VENDAS):
- Add tag: POS_VENDAS
- Move stage: Pós-vendas
- Assign queue: Pós-vendas
- Send text:
"Entendi! 🔄 Vamos cuidar do seu pós-venda.
Informe:
• Número do pedido
• O que aconteceu"
- HANDOFF_TO_HUMAN

IF menu_choice == "4" (ATACADO):
- Add tag: ATACADO
- Move stage: Atacado
- Assign queue: Comercial
- Send text:
"Ótima escolha! 📦
Para compras no atacado, informe:
• Nome / Empresa
• CNPJ (se tiver)
• Produto de interesse"
- HANDOFF_TO_HUMAN

--------------------------------
NODE 4 — END
--------------------------------

================================================
5) HUMAN HANDOFF (MANDATORY)
================================================

When HANDOFF_TO_HUMAN is executed:
- Stop automation immediately
- Mark session.state = "handoff"
- Assign conversation to agent/queue
- Show indicator in UI: "Automation paused – Human handling"

================================================
6) REAL-TIME REQUIREMENTS
================================================

Emit Socket.io events:
- conversation_upserted
- new_message
- automation_started
- automation_step
- automation_handoff
- automation_ended

================================================
7) SAFETY & QUALITY RULES
================================================

- Never block inbound messages
- Never depend on UI state
- Never lose messages
- Never send automated messages after handoff
- Log automation execution steps
