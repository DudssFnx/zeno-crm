REPLIT PROMPT (PT-BR) — AUTOMAÇÃO HÍBRIDA DE CRM WHATSAPP
(Baileys + Fluxo Conversacional + Funil Pipeline + Regras Zoho-Like)

OBJETIVO
========
Construir um sistema de automações e workflows para um CRM WhatsApp que:
1) Recebe qualquer mensagem e nunca perde mensagem
2) Executa um fluxo de triagem inteligível (menu + palavras-chave)
3) Roteia automaticamente o cliente para o setor adequado
4) Aplica regras Zoho-like (workflow/condições/ações/tempo)
5) Gerencia um funil visual tipo pipeline (como Pipedrive)
6) Permite fallback/atendimento humano
7) Não gera SPAM nem risco de banimento do número

REFERÊNCIAS DE MERCADO
======================
- Zoho CRM (regra → ação, workflow avançado)
- Pipedrive (pipeline visual, estágio por estágio)
- Waspeed/Typebot (fluxo conversacional simples e inteligente)
- WATI / Respond.io (roteamento de atendimento)

REGRAS DE ANTI-SPAM (MANDATÓRIO)
================================
✔ Nunca enviar mensagens não solicitadas
✔ Sempre responder mensagens recebidas (Conversa iniciada pelo cliente)
✔ Utilizar menus simples (texto ou botões) com opções claras
✔ Não repetir menus excessivamente
✔ Não bombardear clientes com mensagens automáticas
✔ Inserir delays mínimos entre mensagens automáticas

================================================
A) RECEBIMENTO DE MENSAGENS (OBRIGATÓRIO)
================================================
1) Tratar todos os inbound messages em:
   sock.ev.on("messages.upsert", ...)

2) chatId = msg.key.remoteJid
   - Ignore apenas:
     status@broadcast
     (optional) groups @g.us

3) Sempre:
   - Criar chat se ainda não existir
   - Atualizar lastInboundAt se fromMe=false
   - Atualizar lastMessageAt
   - Emitir ao frontend:
     "conversation_upserted", "wa_new_message"

4) Se o cliente já estiver em um fluxo (flowState), entregar a mensagem ao flow engine.

================================================
B) FLUXO DE TRIAGEM (MENU SIMPLES INTELIGENTE)
================================================
Triagem padrão quando cliente não tem setor/assignedTo:

ENVIO:
------------
“Olá! 👋 Como posso te ajudar hoje?
1️⃣ Vendas
2️⃣ Financeiro
3️⃣ Suporte
4️⃣ Quero falar com um atendente humano”

REGRAS DE RESPOSTA
------------
- Cliente responde com número ou texto
- Se texto contém palavra-chave forte (p.ex., “boleto”, “pagamento”), roteia sem exigir menu
- Bot aceita texto livre (inteligência simples de palavras-chave)

ROTEAMENTO
------------
1 → Vendas
2 → Financeiro
3 → Suporte
4 → Atendimento Humano

================================================
C) WORKFLOW AUTOMÁTICO (ESTILO ZOHO)
================================================
Implementar regras que disparam ações automáticas:

1) Regras baseadas em Evento → Ação:
   - Evento: “Conversão criada”
   - Regra: Se tag=“sem resposta” em 48h
   - Ação: Criar tarefa/reminder

2) Regras de tempo:
   - 3 dias sem inbound → notificar operador
   - 7 dias sem resposta → re-priorizar

3) Condições avançadas (Zoho-like):
   - Se tags contêm X e mensagem contém Y → mover para setor Z
   - Se estágio=“Novo” e inbound=”financeiro” → atribuir FilaFinanceiro
   - Ações podem: adicionar tags, mover estágio, enviar template seguro

4) Não enviar mensagens repetitivas:
   - Verificar último envio similar antes de disparar

================================================
D) FUNIL PIPELINE (ESTILO PIPEDRIVE)
================================================
Conversations devem ter um campo:
conversation.stageId

Exemplo de estágios:
- Novo
- Em Triagem
- Em Atendimento
- Aguardando Cliente
- Concluído
- Fechado

Implementar:
- Visão Kanban por stageId
- Drag & Drop que atualiza stageId no backend
- Filtros por operador, tag, tempo sem mensagem

================================================
E) ROTEAMENTO AUTOMÁTICO
================================================
Configurar roteamento prático:
1) Routing por palavras-chave:
   - “boleto,pagamento,conta” → Financeiro
   - “comprar,preço,produto” → Vendas
   - “erro,defeito,problema” → Suporte

2) Routing por horário:
   - Se fora do horário de atendimento → mensagem de horário e fila

3) Assignment automático:
   - Round-robin entre agentes do setor
   - Atribuir assignedTo no DB

================================================
F) DELIVERY DE MENSAGENS AUTOMÁTICAS (SEM RISCO DE BAN)
================================================
Regras de envio automático:
✔ Somente responder inbound
✔ Não enviar outbound sem inbound recente
✔ Colocar delays naturais
✔ Usar texto simples ou botões curtos
✔ Evitar mensagens em massa

Exemplo permitido:
“Olá! Recebemos sua mensagem, em instantes um atendente irá te responder 😊”

================================================
G) ÁUDIO AUTOMÁTICO OPCIONAL
================================================
Permitir envio de áudio de boas-vindas/setor:
- Enviar apenas se cliente aceitou triagem
- Arquivos .ogg/opus
- Não usar áudio repetitivo

================================================
H) ESTADO DO FLUXO
================================================
Adicionar ao objeto de conversa:
flowState:
{
  flowId,
  currentNode,
  variables,
  updatedAt
}

Ao cada inbound, o flow engine decide:
✔ se continua no fluxo
✔ se termina e marca conversation.departmentId

================================================
I) ATENDIMENTO HUMANO
================================================
1) Cliente escolhe “Falar com atendente”
   → Flow termina, marca humanhandoff
2) assignedTo é setado
3) Operador recebe notificação
4) Bot para de enviar automações naquele chat

================================================
J) MONITORAMENTO DE SPAM/ANTI-BAN
================================================
1) Logar todos envios automáticos
2) Contabilizar resposta do cliente
3) Se baixo engajamento → reduzir automações
4) Não reenviar templates automáticos repetidos

================================================
K) TESTES MÍNIMOS (VALIDADOS)
================================================
1) Numero novo manda mensagem → chat criado + triagem enviada
2) Cliente responde com número → setor correto
3) Sem resposta do cliente por 72h → alerta gerado
4) Palavras-chave roteiam sem menu
5) Atendimento humano funciona

================================================
ENTREGÁVEIS
================================================
1) Flow engine + dataset de nodes
2) Triagem inteligente por menu e keyword
3) Pipeline com Kanban
4) Roteamento automático por regras
5) Anti-spam configurado
6) Atribuição automática de agentes
7) Log de automações
