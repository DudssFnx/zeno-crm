REPLIT PROMPT — PREVENT DUPLICATE BR NUMBERS (+55 / with-9 / without-9) + ONLY ALLOW VALID WHATSAPP NUMBERS + ADD CITY + MAP OF CLIENTS

GOALS:
1) When creating a contact/conversation by typing a number, prevent duplicates caused by Brazilian 9-digit variations (with 9 / without 9) and formatting (+55 or not).
2) Validate if the typed number EXISTS on WhatsApp before allowing creation (anti-spam / avoid multi-chat and wrong numbers).
3) Add “City” field to contacts and show a map with client distribution (where we have clients and where we don’t).

IMPORTANT:
- Do NOT send messages to numbers that don’t exist.
- Do NOT create a conversation if WhatsApp validation fails.
- Be careful with onWhatsApp reliability: add retry + rate-limit and handle errors gracefully.

================================================
A) PHONE NORMALIZATION (BRAZIL-FIRST)
================================================
Implement a single function:

normalizeToDigits(input) => digitsOnly
- Remove spaces, parentheses, dashes, plus sign, and any non-digit.
Example:
"+55 (11) 9 8765-4321" => "5511987654321"
"11 98765-4321" => "11987654321"

Then build E.164-like digits:
- If starts with "55" keep
- Else if length is 10 or 11 (DDD+local), prefix "55"
- Else keep as digits and validate by length rules

Store:
normalized_phone_digits = digits with country code (Brazil: starts with 55)

================================================
B) GENERATE BR CANDIDATE NUMBERS (WITH 9 / WITHOUT 9)
================================================
Brazil has mobile numbering inconsistencies (some accounts may appear with or without extra “9” after DDD).
So generate candidates to check on WhatsApp:

buildBrazilCandidates(normalized_phone_digits):
- Input example: "5511987654321" (55 + DDD 11 + 9-digit mobile)
Candidates:
1) "5511987654321" (with 9)
2) "551187654321"  (without the 9 after DDD) ONLY if pattern matches mobile
- Also handle if user typed without 9:
  input "551187654321" => candidates include with-9 version too.

Rules:
- Brazil format:
  55 + DDD(2 digits) + local(8 or 9 digits)
- Only attempt swap between 8/9 local lengths by adding/removing a single “9” right after DDD.
- Do NOT do random guesses beyond this.

================================================
C) WHATSAPP EXISTENCE CHECK (BAILEYS)
================================================
Before creating any contact or starting a new chat:
- Convert each candidate to JID:
  jid = `${digits}@s.whatsapp.net`
- Call:
  const results = await sock.onWhatsApp(jid1, jid2, ...)

Pick the first result where exists === true.
If found:
- Use result.jid as the canonicalWhatsAppJid
- Allow contact creation
If none exists:
- Block creation and show UI error:
  "Número não encontrado no WhatsApp. Verifique o DDD e o número."

IMPORTANT RELIABILITY:
- Implement retry (max 2 retries) with small backoff if onWhatsApp throws (e.g. status 428 reported by some users).
- Add rate limit: max 1 request/second for onWhatsApp to avoid bans/throttle.
- Log failures for debugging.

================================================
D) PREVENT DUPLICATES IN DATABASE (CANONICAL KEY)
================================================
Once canonicalWhatsAppJid is determined:
- Save contact using a UNIQUE key:
  (instance_id, canonicalWhatsAppJid) UNIQUE

Also store:
- raw_input_phone
- normalized_phone_digits
- canonical_whatsapp_jid
- phone_display (formatted +55 (DD) 9XXXX-XXXX)

When user tries to create again:
- If canonicalWhatsAppJid already exists, open existing conversation instead of creating a new one.

================================================
E) UI FLOW (CONTACT CREATE)
================================================
In the “New Contact / Start Chat” form:
Fields:
